01 · Why local

AI is useful. So why run it yourself?

  • OfflineThe model works on a flight, on a train, anywhere — no connection required.
  • PrivacyYour data stays on your machine. Nothing leaves the room.
  • Saving $You already paid for the hardware. Stop paying again for the tokens.

02 · The moment

The gap has closed

In 2026, a model running on your own machine can rival the frontier APIs. You don't need to be a researcher — just a regular user who asks more than a handful of questions a day.

Reference model: <open_weight_model> — a sparse model that rivals <frontier_model_reference>.

03 · One key concept

Dense vs. sparse (MoE)

  • DenseFires every parameter for every token — the generalist who brings the full toolkit every time. Strongest, but heaviest.
  • Sparse / MoEActivates only the relevant experts per token — frontier-level capability at a fraction of the compute cost.

Tools like LMFIT help match a sparse model to your machine.

04 · Hardware

Know your numbers

Local AI boils down to two numbers.

  • RAMCan it fit? Capacity decides whether the model runs at all.
  • BandwidthHow fast does it run? GB/s decides tokens per second.

04 · Hardware — Capacity

RAM is the hard constraint

If the model doesn't fit in memory, it doesn't run. Period. The variable cost is the KV cache — the buffer that holds your conversation so the model can attend to prior context.

  • Under 128KRoughly <memory_for_local_llm> GB of RAM.
  • Up to 256KThe KV cache grows — up to <placeholder> GB more, depending on the model.

Check total RAM, subtract the OS — whatever remains is what you have to play with.

04 · Hardware — Speed

Bandwidth is the speed

RAM is whether the car fits in the garage.
Bandwidth is how fast it drives on the highway.

More GB/s means more tokens per second. Frontier APIs rely on massive bandwidth clusters to serve users at scale — on your machine, the same physics applies.

05 · Software

Two layers: server + harness

Many options — and it's hard to tell what's good from what's merely popular.

  • ServerServes the model. Turns the weights into a running engine.
  • HarnessSends the prompt, renders the output. Your interface to the model.

05 · Software — Server

Pick a server, keep the defaults

  • MLXDesigned for macOS, optimised for Apple Silicon. Best performance on Mac.
  • GGUFCross-platform. Runs everywhere — not always as optimised on Mac.

Rule of thumb: use default configurations. And don't use Ollama — you'll sacrifice significant performance.

05 · Software — Harness

The harness eats your context

  • Heavy IDEs(e.g. VS Code) inject large system prompts into every request — consuming the context window you paid for in RAM.
  • Light clients(e.g. Pi) leave the context window open for your actual prompt. Smoother experience, pared-back UI.

Reference: Coding Agents & the Harness Tax — arena.ai

06 · Closing

Let's be honest

Copilot on auto, or Claude with Opus, is easier. Zero setup, excellent answers. It always will be.

But for everyday work — writing, coding, research, brainstorming — local AI serves just as well. No subscription, no rate limits, no privacy trade-off. We already own the machines.

We're no longer talking about someday

The question isn't whether local AI can compete.

It's whether you're ready to stop paying for what you can run yourself.

Thank you
