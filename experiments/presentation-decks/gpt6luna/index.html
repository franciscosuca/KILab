02CHOOSE THE MODEL

Dense models do everything.
MoE models route the work.

Dense

ALL PARAMETERS / TOKEN

Every parameter participates for each token. Often straightforward to reason about, but compute-heavy.

Mixture of Experts

SELECTED EXPERTS / TOKEN

A router activates only some experts per token: potentially more capability for less compute.

IMPORTANT Sparse compute does not mean tiny memory needs. The model’s weights still have to be available.

05SERVE THE MODEL

Choose a format your hardware knows well.

A server loads the model and makes it available to your client. The best starting point depends on the machine you own.

01 / APPLE SILICON↗

MLX

Built for Apple silicon. A sensible first option to test on a Mac.

02 / CROSS-PLATFORM↗

GGUF

A widely supported model format across local runtimes and operating systems.

Start with defaults. Then benchmark the same model, quantization, prompt, and context on the server you plan to use. A wrapper or setting can change the result.

07MAKE A FAIR TEST

Find your baseline before you tune.

A simple, repeatable test tells you more than a pile of configuration tweaks.

08THE TAKEAWAY

Use the machine you own.
Use the cloud when it earns its place.

REACH FOR AN API
